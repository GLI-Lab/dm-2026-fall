Labs

Labs are not graded. They are the hands-on companion to each lecture unit. Each lab is a short, focused session designed to help you build intuition for data mining concepts by working directly with data and code. You will load datasets, construct alternative representations, visualize them, and interpret what each representation makes easy — or hides — so that by the time you reach a homework assignment, the underlying data structures feel familiar.

NoteBefore Choosing an Algorithm, Choose a Representation

A dataset does not have only one useful form. The same collection of observations can be a table of records, a sequence, a matrix, a set of transactions, or a graph. Labs in this course start from that idea: the representation you choose determines which algorithms you can apply.

Lab 1: Exploring Data Representations

One notebook, five data types. For each type you will construct several representations of the same underlying data and compare what each one reveals.

  • Lab 1: Exploring Data Representations
    • Part 1. Record data — Titanic (numerical matrix, transactions, binary item matrix, bipartite graph)
    • Part 2. Text data — 20 Newsgroups (token sequences, count matrix, TF-IDF, similarity graph)
    • Part 3. Graph data — Zachary’s Karate Club (visualization, edge list, adjacency list, adjacency matrix)
    • Part 4. Interaction data — MovieLens 100K (utility matrix, binary matrix, bipartite graph, user/item projections)
    • Part 5. Transaction data — Groceries (baskets, long table, binary matrix, co-occurrence graph)

What You Will Receive

Lab 0

Each prerequisite lab is a single guided notebook with explanations and complete, runnable code:

  • python-basics.qmd, numpy-basics.qmd, matplotlib-basics.qmd, pandas-basics.qmd

Lab 1 and later

Starting with Lab 1, each lab is split so that construction and interpretation stay separate:

  • labXX.qmd: The notebook you read and run. It inspects returned objects, visualizes them, and asks you to interpret the results.
  • labXX_*.py: Helper modules that load data and construct representations. You do not need to rewrite these to complete the lab; you import them and study what they return.

For Lab 1 the helpers are lab01_record.py, lab01_text.py, lab01_graph.py, lab01_interaction.py, and lab01_transaction.py.

Graded homework is posted separately on the Assignments page. Starter files will appear in assignments/ as each unit is released.

Workflow

Step 1: Set Up the Environment

Follow the Python Environment Setup guide before opening any lab. Activate the course pixi environment (or use Colab) so that NumPy, pandas, scikit-learn, NetworkX, and the other shared packages are available.

Step 2: Open the Lab Notebook

Launch the notebook using JupyterLab, VS Code, or Google Colab. Each lab opens with a short overview of the data type (or skill) you are about to explore and why it matters for data mining.

NoteRunning Cells in Order

Always run notebook cells from top to bottom. If you skip a cell or run them out of order, later cells may fail because variables or imports from earlier cells are missing.

Step 3: Run and Observe

Unlike the homework assignments, labs do not require you to write code from scratch or fill in TODO blocks. Working code is provided. Your primary task is to run the cells, read the accompanying explanations, and understand how the same observations look as a matrix, a graph, a sequence, or a set of transactions. Pay attention to shapes, sparsity, and what is observed versus derived.

Step 4: Experiment Freely

Labs are exploratory playgrounds. Once you have run the provided code, change things:

  • Subsample users, items, documents, or transactions and watch the representations change.
  • Swap one representation for another (for example, a count matrix vs. TF-IDF, or an adjacency list vs. an adjacency matrix).
  • Break things on purpose — a missing file path, a wrong key, a dense matrix that should have stayed sparse — and read the error.

Tinkering freely is one of the best ways to build intuition before tackling the homework.

Navigating the Notebook Structure

Lab 0

Each prerequisite notebook follows a skill-oriented layout:

  • Objectives lists the specific Python skills you will practice. Read this before you start.
  • Short concept notes explain why that library shows up in data mining workflows.
  • Numbered sections walk through examples you should run in order.

Lab 1

Lab 1 is organized by data type, not by algorithm:

  • Overview states the theme of the lab: one dataset, many representations.
  • Parts 1–5 each load one dataset, build several representations, and visualize or inspect them. Work through the parts in order; later parts reuse the same comparison habit (table → matrix → graph).
  • Think prompts at the end of a part ask you to say what was stored in the original data versus what was derived (for example, an item–item co-occurrence graph).

When a lab imports a labXX_*.py module, treat that file as the place where representations are built, and treat the notebook as the place where you look at the result.
